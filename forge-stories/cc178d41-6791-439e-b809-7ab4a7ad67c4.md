## Goal
Add a concise, self-contained "Check API health inside Compose" section to the local-development wiki page so developers can quickly verify the API is live without needing the port published to their host.

---

## Background & constraints
- `docker-compose.yml` uses `expose: ["3001"]` for the `api` service — port 3001 is **not** mapped to the host via `ports:`, so `curl localhost:3001` from the developer's machine will fail.
- `GET /health` in `src/api/index.js` returns `{"status":"ok"}` (confirmed in source).
- Change is **documentation only**: `forge-wiki/local-development.md` is the sole file to edit.
- No automated tests exist; `test_commands` is empty.

---

## Tasks

### 1. Edit `forge-wiki/local-development.md`
Insert a new top-level section titled `## Check API health inside Compose` after the existing `## Common Commands` section (before `## Development Workflow`). This keeps health-check discovery near other day-to-day commands.

The section must include:

1. **A brief intro sentence** — one line explaining why you run the command inside the container (port 3001 is internal, not published to the host).
2. **The command block:**
   ```bash
   docker compose exec api wget -qO- http://localhost:3001/health
   ```
3. **The expected output block:**
   ```json
   {"status":"ok"}
   ```
4. **A short explanation** clarifying:
   - `localhost` inside the command refers to the `api` container's own loopback, not the developer's machine.
   - Port 3001 is declared with `expose` in `docker-compose.yml`, making it reachable only from other containers on the Compose network, not from the host.
   - A successful response confirms the Express server is up and the health endpoint is reachable.

All existing content in the file must be preserved verbatim.

---

## Acceptance criteria
- `forge-wiki/local-development.md` contains a `## Check API health inside Compose` heading.

- The section includes a clear explanation that port 3001 is internal / not published to the host.
- No other files are modified.
- All pre-existing content in `local-development.md` is intact.
