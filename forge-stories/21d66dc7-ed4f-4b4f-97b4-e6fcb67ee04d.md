## Goal
Add a full delete-task flow: a `DELETE /tasks/:id` REST endpoint on the API and a matching delete button in the frontend UI, so users can permanently remove a task.

---

## Tasks

### 1. API — `src/api/index.js`
Add a new route handler directly after the existing `PATCH /tasks/:id` handler:

```js
// DELETE /tasks/:id — delete a task
app.delete('/tasks/:id', async (req, res) => {
  const id = parseInt(req.params.id, 10);
  const { rowCount } = await db.query('DELETE FROM tasks WHERE id = $1', [id]);
  if (rowCount === 0) return res.status(404).json({ error: 'Not found' });
  res.status(204).send();
});
```

- Parse `:id` as an integer (consistent with the PATCH handler).
- Use `rowCount` to distinguish "deleted" from "not found" without an extra SELECT.
- Return **204 No Content** on success; **404 JSON** if the row didn't exist.

---

### 2. Frontend server action — `src/web/app/actions.ts`
Add a `deleteTask` export after `toggleTask`:

```ts
export async function deleteTask(id: number) {
  await fetch(`${API_URL}/tasks/${id}`, { method: 'DELETE' });
  revalidatePath('/');
}
```

Import it where needed in `page.tsx`.

---

### 3. Frontend UI — `src/web/app/page.tsx`
- Import `deleteTask` from `./actions`.
- Inside the `tasks.map(...)` loop, add a second `<form>` alongside the existing toggle form (or inline the action in a single server action):

```tsx
<form
  action={async () => {
    'use server';
    await deleteTask(task.id);
  }}
>
  <button
    type="submit"
    className="text-zinc-400 hover:text-red-500 transition-colors ml-auto flex-shrink-0"
    aria-label="Delete task"
  >
    {/* ×  or a small trash SVG */}
    <svg viewBox="0 0 16 16" className="w-4 h-4" fill="none" stroke="currentColor" strokeWidth="1.5" strokeLinecap="round" strokeLinejoin="round">
      <path d="M3 4h10M6 4V3h4v1M5 4l.5 9h5L11 4" />
    </svg>
  </button>
</form>
```

Place the delete form after the `<span>` containing the task title so the layout reads: [checkbox] [title] [delete button].

---

## Acceptance Criteria
1. `DELETE /tasks/:id` with a valid existing ID returns **HTTP 204** and the task is removed from the database.
2. `DELETE /tasks/:id` with a non-existent ID returns **HTTP 404** `{ "error": "Not found" }`.
3. Clicking the delete button on a task row in the browser removes that task from the list without a full page navigation (revalidation via server action handles refresh).
4. The rest of the UI (add task, toggle completion, counter) continues to work correctly after a deletion.
5. `docker compose up --build` runs without errors; the app is fully functional at http://localhost:3000.
