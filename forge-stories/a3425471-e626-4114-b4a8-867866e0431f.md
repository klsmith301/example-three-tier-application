# Development Story — API version live test

## Goal
Expose the API's own version string as a lightweight introspection endpoint so callers can confirm which build is running, without touching any deployment configuration.

---

## Tasks

### 1. Add the route — `src/api/index.js`

At the top of the file, require `package.json` once:

```js
const { version } = require('./package.json');
```

Then register the route **before** `app.listen`, alongside the other GET routes:

```js
// GET /api/version — return package version
app.get('/api/version', (_req, res) => {
  res.json({ version });
});
```

That's the entire code change. `require('./package.json')` is valid CommonJS (`"type": "commonjs"` in package.json), costs nothing at runtime, and is evaluated once when the process starts.

---

### 2. Document the endpoint — `forge-wiki/api.md`

Insert a new **Version** section in the **Endpoints** block, between the existing *Health Check* and *List All Tasks* sections:

```markdown
### Version

​```
GET /api/version
​```

Returns the API's current version as declared in `package.json`.

**Response:**
​```json
{ "version": "1.0.0" }
​```
```

No other documentation files need to change.

---

## Acceptance Criteria

| # | Check | How to verify |
|---|-------|---------------|
| 1 | Route responds with HTTP 200 | `curl -s -o /dev/null -w "%{http_code}" http://localhost:3001/api/version` → `200` |
| 2 | Body is valid JSON with a `version` key | `curl -s http://localhost:3001/api/version` → `{"version":"1.0.0"}` |
| 3 | Value matches `package.json` | Compare output with `node -e "console.log(require('./src/api/package.json').version)"` |
| 4 | No hardcoded string in `index.js` | `grep -n '"1\.' src/api/index.js` returns no match on the version line |
| 5 | Existing routes unaffected | `curl http://localhost:3001/health` still returns `{"status":"ok"}` |
| 6 | No deployment files changed | `git diff --name-only` lists only `src/api/index.js` and `forge-wiki/api.md` |

---

## Smoke-test procedure (no test suite present)

```bash
# 1. Start the API (requires a reachable DATABASE_URL or the full Docker stack)
docker compose up --build api

# 2. In a second terminal
curl -s http://localhost:3001/api/version
# Expected: {"version":"1.0.0"}

# 3. Confirm status code
curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3001/api/version
# Expected: 200

# 4. Confirm existing health route still works
curl -s http://localhost:3001/health
# Expected: {"status":"ok"}
```
