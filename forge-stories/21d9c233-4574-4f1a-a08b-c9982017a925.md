## Goal
Remove the DELETE /tasks/:id endpoint from the API and fully unwire it from the frontend — no trace of the feature should remain.

---

## Tasks

### 1. `src/api/index.js` — drop the DELETE route
Delete the entire `app.delete('/tasks/:id', ...)` block (≈5 lines). No other changes to this file are needed.

### 2. `src/web/app/actions.ts` — remove the `deleteTask` export
Delete the `deleteTask` function (≈4 lines). The `revalidatePath` import and all other exports (`getTasks`, `createTask`, `toggleTask`) must remain untouched.

### 3. `src/web/app/page.tsx` — remove the delete UI
- Remove `deleteTask` from the named import at the top of the file.
- Inside the `tasks.map(...)` block, delete the second `<form>` element entirely — the one whose `action` calls `deleteTask(task.id)`, which includes the trash-icon `<svg>` and its containing `<button>`.

---

## Acceptance Criteria
- `DELETE /tasks/:id` returns a 404 or connection error (route no longer registered).
- No delete button or trash icon appears in the task list UI.
- `deleteTask` is not referenced anywhere in `src/web/`.
- Adding, listing, and toggling tasks continue to work normally.
- `npm run lint` in `src/web/` passes (no unused-import warnings for `deleteTask`).
